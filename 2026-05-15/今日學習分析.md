**今日核心問題解答**（W4 Day 3 帶入的問題）：

> `useWatchEffectLogger` 要怎麼支援動態切換 flush 模式？

**答**：在 Composable 內用 `watch(flushMode, buildEffect)` 監聽模式變化。`buildEffect` 負責「停止舊 effect → 用新 flush 建立新 effect」。由於在 `watch` callback 中建立的 `watchEffect` 不在 setup 同步流中，不會自動綁定 Active Instance，所以需要在 Composable 初始化時（setup 同步流）登錄 `onUnmounted` 來確保最終清理。這樣使用端只需修改 `flushMode.value`，不需要知道內部重建的細節。

## 概念鞏固：用自己的話解釋

### Q1：為什麼動態切換 flush 模式必須重建 watchEffect？

`watchEffect` 的 `flush` 選項決定了「這個 watchEffect 在 Vue 更新週期的哪個時間點執行」。這個時間點是在 `watchEffect` 建立時就以「觀察者」的角色注冊進 Vue 的排程系統（scheduler）的——就像預訂一個固定座位，換座位的方法只有離座（停止）後重新預訂（重建）。

你沒有辦法「修改」一個已建立的 watchEffect 的 flush 選項，只能：
1. 停止舊的（`stopEffect()`）
2. 用新的選項建立新的（`watchEffect(fn, { flush: newMode })`）

### Q2：`wasCleanedUp` 為什麼要用閉包而不是放在 callback 內部？

`watchEffect` 的 callback 每次執行都是一個新的函式呼叫，所有在 callback 內部宣告的變數都是「這次執行的局部變數」，執行完就消失了。

我需要知道的是「**上一次執行**的 cleanup 是否有被呼叫」——這個資訊屬於「跨執行輪次的狀態」，必須儲存在比 callback 更外層的作用域：

```ts
// 閉包中的 wasCleanedUp 跨執行輪次持久
let wasCleanedUp = false

stopEffect = watchEffect((onCleanup) => {
  const cleanupTriggered = wasCleanedUp  // 讀取上一次的狀態
  wasCleanedUp = false                    // 重置

  onCleanup(() => {
    wasCleanedUp = true  // 寫入，下一次執行能讀到
  })
  // ...
})
```

### Q3：`onUnmounted` 的「登錄時機」和「清理時機」有什麼區別？

- **登錄時機**：必須在 `setup()` 同步呼叫流中（Active Instance 存在時）。這樣 Vue 才知道這個清理函式屬於哪個元件。
- **清理時機**：在元件卸載時執行（`onUnmounted` callback 執行時）。

這兩件事是分開的。你可以在 setup 初始化時登錄 `onUnmounted`，而在 `onUnmounted` callback 中清理的是「變數 `stopEffect` 當下指向的 effect」——無論這個 effect 是在 setup 同步流中建立的，還是在後來的 watch callback 中建立的。
