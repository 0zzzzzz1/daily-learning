## 四、概念鞏固 — 用自己的話解釋

### Q：`reactive` provide 和普通值 provide 有什麼差別？

**回答**：

```ts
// ❌ provide 普通值：後代 inject 拿到的是值的 snapshot（凍結在那個瞬間）
provide(panelThemeKey, { borderRadius: 'md', shadow: 'sm', headerBg: '#blue' })
// 之後修改任何東西，inject 端都感知不到變化

// ✅ provide reactive：後代 inject 拿到的是 Proxy 本身
const theme = reactive<PanelTheme>({ borderRadius: 'md', shadow: 'sm', headerBg: '#blue' })
provide(panelThemeKey, theme)
// 之後 theme.headerBg = '#red' → inject 端自動更新（因為是同一個 Proxy）
```

規律：只要 `inject` 拿到的是 `ref` 或 `reactive` 物件，就有響應性；如果是普通值（number、string、object literal），就沒有。

---

### Q：`DashboardLayout.vue` 中的 `as const` 和 `keyof typeof` 是什麼作用？

**回答**：

```ts
// 沒有 as const：TypeScript 認為 panels 的值是 Component（寬泛型別）
const panels = {
  form: FormPanel,   // 型別推導為：{ new(): ... }（元件建構子，但寬泛）
  list: ListPanel,
}
type PanelKey = keyof typeof panels  // 'form' | 'list'（OK）

// 有 as const：TypeScript 認為 panels 的每個 key-value 是精確的字面量
const panels = {
  form: FormPanel,
  list: ListPanel,
} as const
// 額外效果：panels.form 不能再被覆寫（唯讀）
type PanelKey = keyof typeof panels  // 'form' | 'list'（更精確、更安全）
```

對 `<component :is="panels[currentPanel]" />` 而言，TypeScript 能確認 `panels[currentPanel]` 一定是一個 Vue 元件定義物件，而不是 `any`，所以不報錯。
