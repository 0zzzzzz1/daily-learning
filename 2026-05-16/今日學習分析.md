**昨日帶入問題解答**：

> `triggerUpdate.value++`，但 `triggerUpdate` 沒有在模板中渲染，`onUpdated` 是否會被觸發？

**答**：**不會**。Vue 的依賴追蹤原則：響應式資料必須在 render function（模板）中被「讀取」，才會建立依賴關係。沒有被追蹤的資料改變，Vue 根本不知道需要重新渲染，因此既不會觸發 re-render，也不會觸發 `onUpdated`。正確做法是在模板中加入 `{{ triggerUpdate }}` 或讓 `triggerUpdate` 影響一個在模板中被讀取的 computed 值。

## 概念鞏固：用自己的話解釋

### Q1：為什麼 `triggerUpdate.value++` 不一定能觸發 `onUpdated`？

Vue 的響應性系統是「讀取建立依賴，寫入通知更新」——這是它高效的根本原因。

當 render function（模板被編譯成的函式）執行時，Vue 會記錄「這個元件的渲染依賴哪些響應式資料」。只有被 render function **讀取過**的響應式資料，才會被加入元件的依賴列表。

如果 `triggerUpdate` 在模板中沒有任何地方被讀取，render function 就不知道它的存在，也就沒有建立依賴關係。當你做 `triggerUpdate.value++` 時，Vue 確實收到了「資料改變」的通知，但找不到任何元件依賴它，於是什麼都不做。

結論：**改變響應式資料只是「通知」，有沒有人「訂閱」才決定是否觸發重新渲染。**

### Q2：在 `useLifecycleLogger` 中，`hookCounts` 用 `reactive` 而不用 `ref`。`resetAll` 怎麼把 reactive 物件的值歸零而不失去響應性？

`reactive` 物件不能整批替換（直接 `hookCounts = {...}` 會失去響應性，因為舊的 Proxy 被拋棄了）。

正確的做法是**原地修改每個屬性**：

```ts
function resetAll(): void {
  logs.value = []  // ref 可以整批替換
  // reactive 的每個屬性逐一歸零（原地修改，Proxy 追蹤到改變）
  ;(Object.keys(hookCounts) as Array<keyof HookCounts>).forEach((key) => {
    hookCounts[key] = 0
  })
}
```

這就是為什麼日誌陣列選擇 `ref`（整批替換 `logs.value = []` 既清晰又安全），而計數物件選擇 `reactive`（結構固定，用原地修改就好）——兩種資料結構有不同的最適合的響應式工具。

### Q3：`useLifecycleLogger` 和 `useWatchEffectLogger` 都有各自的 `onUnmounted`。它們會彼此干擾嗎？

不會。Vue 的 Active Instance 機制允許多個 Composable 在同一個元件的 `setup()` 同步流中各自登錄 lifecycle hook。這些 hook 都會被綁定到同一個元件實例，在元件卸載時全部按登錄順序觸發，彼此獨立、互不干擾。

這正是 Composable 設計模式的核心價值：**封裝邏輯（包括 lifecycle 副作用），組合使用，卻不互相耦合。**
