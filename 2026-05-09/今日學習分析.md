## 概念鞏固：用自己的話解釋

**Q1：`onMounted` 為什麼能在 Composable 中使用？**

**A：**

Vue 3 在元件執行 `setup()` 函式的期間，會設定一個「Active Instance」（當前活躍的元件實例）。任何在 `setup()` 同步執行過程中被呼叫的 `onMounted`（不論是直接呼叫還是透過 Composable 間接呼叫），都會被自動綁定到這個 Active Instance。

這意味著：
```typescript
// 元件 setup() 執行時
setup() {
  useTasks()  // 內部的 onMounted 在這個時機點被呼叫
              // Vue 自動將它綁定到這個元件的實例
}
```

**條件**：`useTasks()` 必須在 `setup()` 的**同步執行流**中被呼叫，不能在非同步的回呼中呼叫，否則 Vue 已經無法知道要綁定到哪個元件。

---

**Q2：為什麼 `as Task[]` 不夠，還需要型別守衛？**

**A：**

`as Task[]` 是 TypeScript 的「型別斷言」（Type Assertion）——它告訴 TypeScript 編譯器「相信我，這個值是 `Task[]`」。TypeScript 照單全收，**不做任何執行期檢查**。

實際上 `JSON.parse(raw)` 回傳的是 `any`，執行期的真實型別完全取決於 `raw` 字串的內容。如果 localStorage 中儲存的是舊版格式（沒有 `createdAt` 欄位），那麼：

```typescript
const savedTasks = JSON.parse(raw) as Task[]  // TypeScript 相信我們
savedTasks.forEach(task => {
  console.log(task.createdAt.toFixed(0))  // 執行期：TypeError，因為 createdAt 是 undefined
})
```

型別守衛在執行期真正驗證每個欄位，把「TypeScript 承諾的安全」變成「實際上的安全」。

---

**Q3：`watch(tasks, ..., { immediate: true })` 和 `onMounted` 讀取有什麼不同？為什麼不用 immediate？**

**A：**

`watch` 的語義是「監聽變化，有變化就執行副作用」。即使加了 `immediate: true`，它的語義仍然是「監聽」——用來**寫入**（反應式地把 tasks 的變化同步到 localStorage）。

`onMounted` 的語義是「元件掛載完成後，執行一次性的初始化」——用來**讀取**（從 localStorage 恢復上次的狀態）。

如果用 `watch(tasks, ..., { immediate: true })` 做讀取：
1. `immediate: true` 會在 `watch` 建立時立即執行一次 callback，這時 `tasks.value` 是初始的空陣列 `[]`
2. 這會把 localStorage 中的舊資料**覆蓋掉**（`setItem('tasks', '[]')`）
3. 完全錯誤！

正確的設計就是：**`onMounted` 負責讀，`watch` 負責寫**，各司其職。
