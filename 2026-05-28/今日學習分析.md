## 四、概念鞏固（用自己的話解釋）

### Q：ListPanel.vue 的 `generic="T"` 解決了什麼問題？不用泛型的話會怎樣？

**A**：`generic="T"` 讓 `ListPanel` 的 items 可以是「任意型別的陣列」，而且 TypeScript 知道每個 item 的型別。

具體機制是：
1. `<script setup lang="ts" generic="T">` 告訴 Vue：「這個元件的 T 是型別參數」
2. `defineProps<{ items: T[] }>()` 讓 Props 型別化（items 是 T 的陣列）
3. Scoped Slot 暴露 `<slot :item="item" />` 時，item 的型別就是 T
4. 使用端 `<ListPanel :items="tasks">` 時，TypeScript 從 `tasks: Task[]` 推導出 T = Task
5. 所以使用端的 `#default="{ item }"` 中，item 被正確推導為 `Task` 型別

不用泛型（改用 `items: unknown[]` 或 `items: any[]`）的話：
- `unknown[]`：Scoped Slot 的 item 型別是 unknown，使用端每次存取都要自己斷言或 type guard，很麻煩
- `any[]`：型別系統完全放棄，TypeScript 無法提供任何保護

泛型讓這個元件成為「型別安全的通用容器」——item 是什麼型別，完全由使用端的 `:items` 決定。

---

### Q：為什麼 `inject(key)` 不帶 fallback 時要特別小心？

**A**：`inject(key)` 不帶 fallback 時，回傳型別是 `T | undefined`。

這表示：
1. TypeScript 知道你可能沒有 `provide` 這個 key
2. 後續如果直接 `theme.borderRadius`，TypeScript 會報錯（可能是 undefined）
3. 你必須做 null check：`if (theme) { ... }` 或使用 `!` 非空斷言

帶 fallback：`inject(key, defaultTheme)` 回傳型別是 `T`（不含 undefined），因為即使沒有 provide，fallback 保證一定有值。這讓後續程式碼更乾淨，不需要到處做 null check。

選用建議：
- 若 inject 的值是「可選的配置」（如 theme），一定要帶 fallback → 定義預設值，讓元件在缺少 provide 時仍能正常運作
- 若 inject 的值是「必要的依賴」（如 store、router），不帶 fallback + 做明確的 null check 更能在開發期暴露錯誤
