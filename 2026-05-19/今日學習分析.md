## 概念鞏固：用自己的話解釋

### Q1：為什麼不能在子元件對 props 直接 `v-model` 綁定？

`v-model` 是 `:value + @input + 直接賦值` 的語法糖。當你寫 `<input v-model="props.modelValue" />` 時，使用者輸入會觸發 Vue 嘗試**直接修改** `props.modelValue`。

但 Props 是父元件「借給」子元件的資料，子元件沒有所有權，不能直接改。這違反了 Props Down 原則——父元件不知道資料被改了，沒有機會做驗證或決策。

正確方式是：子元件「只讀取 props.modelValue（透過 `:value`），改變時透過 emit 告訴父元件（`emit('update:modelValue', 新值)`），父元件自己決定要不要更新」。這樣資料流向是可預測且可追蹤的。

### Q2：`withDefaults` 解決了什麼問題？

TS 型別宣告裡，`placeholder?: string` 表示 optional，所以它的型別是 `string | undefined`。後續使用 `props.placeholder` 時，TypeScript 會提醒你它可能是 `undefined`，要你做防禦處理。

`withDefaults` 讓你補充「當父元件沒傳這個 prop 時用什麼值」，同時讓 TypeScript 知道這個 prop **不會是 undefined**（因為有預設值兜底），後續存取型別更乾淨。

等效關係：`withDefaults(..., { placeholder: '' })` → TypeScript 把 `placeholder` 的型別從 `string | undefined` 縮窄為 `string`。

### Q3：`v-model:title="post.title"` 在父元件和子元件分別代表什麼？

**父元件**：  
`v-model:title="post.title"` 展開為 `:title="post.title"` + `@update:title="post.title = $event"`

**子元件的 defineProps**：  
需要接收名為 `title` 的 prop（不是 `modelValue`，因為是具名 v-model）

**子元件的 defineEmits**：  
需要 emit `'update:title'`（不是 `'update:modelValue'`）

規律：`v-model:propName` → prop 名稱 = `propName`，emit 名稱 = `'update:propName'`

## 今日知識地圖

```
元件通訊（M2-W5 主軸）
│
├── Props（父 → 子，單向）
│   ├── defineProps<Interface>()         ← TS 型別宣告（推薦）
│   ├── withDefaults(..., {...})         ← 補充 optional props 預設值
│   └── 子元件只能讀取，不能直接修改
│
├── Emits（子 → 父，事件通知）
│   ├── defineEmits<{ event: [payload] }>()  ← TS 型別宣告
│   ├── emit('update:modelValue', 新值)      ← v-model 專屬命名
│   └── emit('blur', event)                  ← 一般事件
│
└── v-model（雙向語法糖）
    ├── 基本：v-model="val"
    │   └── 展開：:modelValue="val" + @update:modelValue="val=$event"
    ├── 具名：v-model:title="val"
    │   └── 展開：:title="val" + @update:title="val=$event"
    ├── 多個：v-model:a + v-model:b
    └── defineModel（Vue 3.4 簡化語法）
        └── 回傳可寫入 ref → 讀 = 讀 prop，寫 = emit
```
