```markdown
## 這個 PR 做了什麼
重寫 W1 版 TaskList.vue，以 Composable 架構（useTasks.ts）解耦邏輯與 UI，
整合 W3 所有響應式 API：ref、reactive、computed、watch、onMounted。

## 為什麼這樣設計

### 1. 為什麼用 `ref<Task[]>` 而非 `reactive({ tasks: Task[] })`
ref 提供整批替換語義（`tasks.value = [...]`），讓 trigger 時機可預測，
且解構時不會失去響應性（因為 Composable 本身不解構這個 ref）。

### 2. 為什麼 `useTasks` 不用 `toRefs` 回傳
Composable 回傳的 `tasks`、`filteredTasks` 本身已經是 ref，
使用 toRefs 是為了解構 reactive 物件，這裡不適用，
強制使用反而增加理解成本。

### 3. 為什麼 `clearDone` 使用 filter 而非 splice
filter 的 no-op 特性：當 id 不存在時自然回傳原陣列，
不需要額外防禦邏輯，符合函數式無副作用原則。

### 4. 為什麼 checkbox 用 `:checked + @change` 而非 `v-model`
v-model 直接綁定 computed 的屬性欄位，會破壞單向資料流，
讓 UI 直接修改衍生狀態。正確做法是透過 toggleDone 方法通知 State 更新。

## 如何驗證
參見 `作業驗收腳本`（16 步驟功能 Checklist）
vue-tsc 輸出：零錯誤、零警告
```

## W3 自我檢核問題（PR 提交前最後確認）

提交前用這 5 個問題檢查自己的理解是否紮實：

1. **`watch` 和 `watchEffect` 的依賴追蹤機制有何根本差異？**
   > 答：`watch` 明確指定依賴（lazy，惰性）；`watchEffect` 自動追蹤，但追蹤邊界只在第一個 `await` 之前的同步程式碼。

2. **為什麼 `computed` 有「快取」，而 `method` 沒有？**
   > 答：`computed` 使用 `_dirty flag`：依賴改變時只設 dirty，不立即重算，等讀取時才執行 getter；`method` 每次呼叫都執行。

3. **`toRef` 和 `ref` 的本質差異是什麼？**
   > 答：`ref` 是獨立儲存值；`toRef` 不存值，每次讀寫都透過原物件的屬性——它是「連動參考」，不是獨立狀態。

4. **為什麼 `onMounted` 在 `useTasks.ts`（Composable）裡能正常工作？**
   > 答：Vue 的 Active Instance 機制：只要在 `setup()` 的同步執行流中呼叫的函式，都能正確綁定生命週期，Composable 在 `setup()` 中呼叫，所以有效。

5. **TypeScript `as Task[]` 和 `item is Task` 型別守衛的根本差異？**
   > 答：`as T` 是編譯期承諾（只讓 TS 閉嘴），執行期不保證；`item is Task` 守衛函式在執行期逐欄位驗證，是真正的型別安全。

## W4 預告：Lifecycle Hooks × watchEffect × toRefs（5/12 起）

W3 已建立響應式資料流的完整掌握。W4 聚焦在**元件生命週期與副作用管理的進一步深化**。

### W4 核心概念預覽

#### 1. 生命週期完整時間軸

```
beforeCreate → created → beforeMount → mounted
                                         │
                              使用者互動觸發更新
                                         │
                         beforeUpdate → updated
                                         │
                              元件從 DOM 移除
                                         │
                         beforeUnmount → unmounted
```

W3 已用到 `onMounted`；W4 會深入：
- `onBeforeMount`：DOM 尚未建立前執行（可存取資料，不可存取 DOM）
- `onUnmounted`：清理副作用（clearInterval、abort fetch、removeEventListener）
- `onUpdated`：DOM 更新後執行（避免無限循環）

#### 2. `watchEffect` 深化

W3 已知：依賴追蹤只在首個 `await` 之前。W4 會深入：
- `onCleanup`：處理 Race Condition
  ```ts
  watchEffect((onCleanup) => {
    const controller = new AbortController()
    fetch(url, { signal: controller.signal })
    onCleanup(() => controller.abort()) // 下次執行前取消上次請求
  })
  ```
- `flush: 'post'`：需要 DOM 更新後才能執行的副作用

#### 3. `toRefs` 在 Composable 的角色（深化）

W3 已知：`toRefs` 讓 reactive 物件可以解構且保持響應性。W4 場景：
```ts
// W4 Composable 典型回傳模式
function useTimer() {
  const state = reactive({ count: 0, isRunning: false })
  // ... 方法 ...
  return { ...toRefs(state), start, stop } // 解構後仍響應
}
```

### W4 預期產出

**生命週期觀察工具**：一個 Vue 3 元件，能視覺化顯示生命週期觸發順序，
並整合 `watchEffect` 的 onCleanup 模式處理非同步副作用。
