## 四、概念鞏固（用自己的話解釋）

### Q：為什麼 usePanelTheme 的查找表要放在函式「外面」（module 層級），而不是每次呼叫時建立？

**A**：`borderRadiusMap`、`shadowMap` 等查找表是**靜態常數**——它們的內容永遠不會改變，和呼叫 usePanelTheme 的元件無關。

如果放在函式內部：
```typescript
export function usePanelTheme() {
  // ⚠️ 每次呼叫都建立新物件，浪費記憶體
  const borderRadiusMap = { none: 'rounded-none', sm: 'rounded-sm', /* ... */ }
  // ...
}
```

三個 Panel 都呼叫 `usePanelTheme()`，就會建立三份相同的查找表物件，佔用不必要的記憶體。雖然這個例子的查找表很小，影響微乎其微，但建立正確習慣很重要——靜態資料屬於 module 層級，動態狀態（`inject` 的結果、`computed`）才屬於函式內部。

---

### Q：三個 Panel 呼叫 inject(panelThemeKey, defaultTheme)，它們拿到的是同一個物件嗎？

**A**：是的，拿到的是同一個 **reactive Proxy 的參考**。

`DashboardLayout` 做了 `provide(panelThemeKey, reactive(theme))`，`reactive(theme)` 建立了一個 Proxy 物件。三個 Panel 各自呼叫 `inject(panelThemeKey, ...)` 時，Vue 沿著元件樹向上找到 DashboardLayout 的 provide，回傳的是**同一個 Proxy 的參考**，不是複製品。

這就是為什麼切換 theme 時三個 Panel 同步更新——它們共享同一個響應式物件。如果 inject 回傳的是複製品，每個 Panel 會有自己的獨立狀態，就無法同步了。

**設計含義**：這也意味著三個 Panel 理論上都能修改 theme（因為拿到的是同一個可寫的 reactive 物件）。若要防止後代元件意外修改 theme，應該用 `readonly` 包裝：`provide(panelThemeKey, readonly(reactive(theme)))`。
