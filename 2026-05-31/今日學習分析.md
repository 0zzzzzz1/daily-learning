## 四、概念鞏固（用自己的話解釋）

### Q1：為什麼 Composable 回傳值不能直接回傳 `reactive` 物件？

**A**：`reactive` 物件是 Proxy，解構它時只是把 Proxy 內部的值取出來複製，這個複製出來的值是普通的 JavaScript 值，**不帶有響應性**。

```typescript
// ❌ 錯誤
function useCounter() {
  const state = reactive({ count: 0 })
  return state
}
const { count } = useCounter()  // count 是 number，不是 ref
count++  // 不會觸發任何更新

// ✅ 正確 — 回傳 ref（本身就是帶響應性的物件，解構後仍是 ref）
function useCounter() {
  const count = ref(0)
  return { count }
}
const { count } = useCounter()  // count 是 Ref<number>
count.value++  // ✅ 觸發響應性更新
```

### Q2：你有一個功能元件 `UserDashboard.vue`，裡面 fetch 了 3 個不同的 API，每個都有 loading/error/data 三種狀態，程式碼已經 150 行了。你應該如何重構？

**A**：這是典型的「重複樣板」訊號，應提取 `useAsyncData<T>` Composable：

```typescript
// 提取前（重複 3 次）：
const usersLoading = ref(false)
const usersData = ref<User[]>([])
const usersError = ref<Error | null>(null)
// ... fetch users 邏輯

const ordersLoading = ref(false)
// ... fetch orders 邏輯（相同結構）

// 提取後（乾淨）：
const { data: users, loading: usersLoading, execute: fetchUsers } = 
  useAsyncData<User[]>((signal) => fetchAPI('/users', signal))

const { data: orders, loading: ordersLoading, execute: fetchOrders } = 
  useAsyncData<Order[]>((signal) => fetchAPI('/orders', signal))
```

重構的判斷依據：三個地方出現了**完全相同的響應式結構 + 相同的非同步邏輯**，是最清楚的提取訊號。
